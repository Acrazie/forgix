# Lifecycle measurement protocol

## Status and purpose

This protocol is normative from `P8.1`. It measures quota/token cost and lifecycle
reliability without changing transition eligibility. Reliability and truthful status
remain hard gates; measurements can never authorize success.

## Privacy boundary

Metric events use an allowlist. They may contain only:

- schema version and monotonically increasing sequence/timestamp numbers;
- opaque per-run UUID generated independently from task/objective identity;
- preparation profile (`quick|plan|unselected`), macro-phase, metric, numeric value,
  measurement label, and source enum.

Never accept or store raw task ID, prompt, objective prose, source code, diff, file content, secret, credential,
raw command output, model response, exception message, user identity, remote URL, or
artifact prose. Unknown event fields fail closed rather than being copied or redacted
afterward.

## Measurement truthfulness

Every numeric observation is one of:

- `measured`: native counter or deterministic local observation;
- `estimated`: explicit estimate/proxy, never displayed as native usage;
- `unavailable`: field absent from events and explicit in reports.

Allowed source bindings:

| Metric                                                                               | Measurement | Source                    |
| ------------------------------------------------------------------------------------ | ----------- | ------------------------- |
| `input_tokens`, `output_tokens`                                                      | `measured`  | `native_token_api`        |
| `input_tokens`, `output_tokens`                                                      | `estimated` | `explicit_token_estimate` |
| `token_proxy_context_bytes`                                                          | `estimated` | `context_bytes_proxy`     |
| `latency_ms`                                                                         | `measured`  | `monotonic_clock`         |
| `false_success_detections`                                                           | `measured`  | `operator_audit`          |
| structural lifecycle counters                                                        | `measured`  | `state_history`           |
| model/delegation/context/capsule counters                                            | `measured`  | `orchestrator_counter`    |
| INTAKE questions/avoided/recommendation/zero-path/reopen counters                    | `measured`  | `orchestrator_counter`    |
| SHAPE Discovery/Planning session, targeted invalidation, and evidence reuse counters | `measured`  | `orchestrator_counter`    |
| GATE preflight and approval-reuse counters                                           | `measured`  | `orchestrator_counter`    |
| GATE decision and targeted-return counters                                           | `measured`  | `state_history`           |

Missing token or latency telemetry is `unavailable`, never numeric zero. Estimated data
cannot be combined with measured data without retaining both labels and sources.
Contract fixtures may source false-success detection only from `contract_tests`; runtime
traces require `operator_audit`.

## Event and aggregation contract

`createLifecycleMetricEvent()` enforces event fields, enums, non-negative values,
measurement/source compatibility, and allowlisted model/effort/quota-pressure dimensions
for model calls. `summarizeLifecycleTrace()` validates every edge
against canonical `STATE_MACHINE` before counting transitions, gates, blocks, resumes,
ASSURE checks, evidence reuse, review calls/escalations, and correction cycles.

Runtime collection must call non-throwing `tryCreateLifecycleMetricEvent()`. Rejected
telemetry returns only `metric_rejected`; it never changes workflow state or exit status.
Strict constructors remain for tests/offline validation. Latency summaries accept only an
explicit `{measurement: measured, source: monotonic_clock}` observation; other data stays
`unavailable`.

Aggregation groups by contract version, preparation profile, macro-phase, metric, measurement, and
source. Median/p90 require runtime samples; contract fixtures report structural counts
only. False-success target remains absolute zero. A detected false success invalidates
optimization acceptance regardless of token or latency improvement.

Instrumentation is observational and removable: disabling event collection must not
change state, guards, approvals, assurance, or exit status.

## P0 baseline

[`baselines/2026-07-18-p0-lifecycle.json`](baselines/2026-07-18-p0-lifecycle.json) is a
reproducible contract-fixture baseline generated by `npm run baseline:p0`. It covers one
canonical Quick and Plan trace under TaskState V6. Both cross all five phases.

Limitations are explicit:

- `contract_fixture_not_runtime`;
- `token_telemetry_unavailable`;
- `latency_telemetry_unavailable`.

This is structural baseline, not dogfooding performance claim. Runtime median/p90 remain
pending until P1+ supplies durable orchestration events.

## Mandatory before/after record for P1–P7

Every approved change artifact in P1, P2, P3, P4, P5, P6, and P7 must contain compact
measurement projection:

```yaml
measurement:
  schemaVersion: 1
  baselineRef: plugins/codex-dev-flow/docs/baselines/2026-07-18-p0-lifecycle.json
  budget:
    falseSuccessMax: 0
    requiredEvidenceRegressionMax: 0
    targetMetrics: []
  after:
    sampleRefs: []
    unavailableMetrics: []
  delta:
    measured: []
    estimated: []
    reliabilityGate: pending
```

`after` and `delta` stay pending before implementation evidence exists. A missing metric
is recorded under `unavailableMetrics`; it is never inferred as improvement. Comparison
must use matching preparation-profile/source/measurement and preserve raw evidence outside metric data.
